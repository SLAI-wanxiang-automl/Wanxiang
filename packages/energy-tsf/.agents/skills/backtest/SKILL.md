# Backtest

## 何时使用

当用户要求评估已有场站当前模型在近期真实数据上的表现，并更新集成权重时使用。预测未来用 `forecast`，首次建模用 `modeling`；重新训练、重搜参数或增删模型属于后续 `update`，不由本 Skill 执行。

仓库内不注册回测智能体。外部宿主 Agent 只负责理解自然语言、补齐字段和调用入口；窗口、上下文、指标、贝叶斯更新及发布均由确定性代码完成。

## 必须明确的输入

- 场站 ID；该场站必须已有同目标、同频率的 Active；
- CSV/Parquet 真值文件、目标列、时间戳列、采样频率和时区；
- 输入全部视为测试真值，不能混入未标识的上下文数据。

第一版 horizon 和 stride 都固定为 `1d`。默认更新并发布；用户只要求评估时使用 `--no-publish`。

## 执行步骤

1. 将自然语言转换为 `BacktestRequest`。
2. 调用 `prepare-backtest` 生成 request、TOML 和 resolved 配置。
3. 调用 `inspect-backtest` 固定同站 Active、检查训练快照和逐日窗口；无同站 Active 时停止，不检索相似站。
4. 调用 `run-backtest` 做只读逐窗推理、指标和贝叶斯更新。
5. 报告各成员、更新前后集成、旧/新权重和发布结论。

## 关键约束

- 任一窗口上下文只能包含严格早于其 origin 的记录；
- 不调用 fit/save，不改变模型、参数、特征或成员集合；
- 缺失真值不参与指标；
- 新权重必须形成新 Solution，不能原地改写父版本；
- 发布前 Active 必须仍指向计划中的父 Solution；
- 新集成整体 RMSE 变差时保留报告但不切换 Active。

## 完成标准

必须生成冻结 plan、逐点预测、指标、权重证据、机器报告、人类报告和结果文件。请求发布时还应生成新 Solution/Candidate，并在门禁通过后原子更新 Active。
